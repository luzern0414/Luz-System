## 能做什么

- **系统方案**：确认模块范围，用真实浏览器调研同类产品，写出系统架构（角色、功能、页面、动作、流程与异常、界面状态、外部集成、追溯矩阵），再出系统设计网页。
- **界面功能设计**：按七层规范（设计架构、功能架构、信息架构与导航、页面内容与优先级、组件、视觉交接、文案）设计网页管理后台、小程序、智能体和网站四个端的页面、入口、标签栏、组件和按钮动作，每端有自己的细则；视觉（构图、卡片、按钮外观、图标、配图、动效、主题）归 [Luz-Design](https://github.com/luzern0414/Luz-Design)，职责对照见它的 `references/ui-ownership.md`。
- **可交互原型**：把系统功能列表、小程序和后台放进一个自包含的 HTML，在浏览器里逐页验收，并检查手机宽度下的可操作性；行为、数据和场景由本技能规定，外观由 Luz-Design 规定。
- **客户文件的内容**：功能清单（模块、功能、使用端、角色、基础或可选、业务逻辑、工时）、方案说明书的需求分析与解决方案、系统架构图册的节点与数据流；交给客户的只有 PDF 和 Excel，由 Luz-Project 与 Luz-Design 据数据文件生成，本技能负责内容与检查（`features_check.py`）。
- **硬件设计**：先写清业务的完整流程，再把每个环节对应到现场设备，写明设备之间的接口与协议、断网兜底和供电网络要求，核对型号、价格与采购渠道，输出带系统连接图的选型清单（评审用网页，客户用 Excel，`hw_export.py`）。
- **质量把关**：模块、架构、系统设计、视觉、原型各有一次人工批准，硬件选型清单发布前也要人工批准，都记录文件哈希；脚本校验结构、追溯关系和交付文件。
- **阅读页的字体层级**：模块表单、系统架构、系统设计网页和硬件选型清单按 Markdown 渲染的样子排字，桌面正文 18、手机 16，标题、表格、代码各有固定一档（样式取自 `references/md-type.css`，规则见 [Luz-Design](https://github.com/luzern0414/Luz-Design) 的文件设计规范“排版参数”）；后台、小程序、智能体、网站这些产品界面沿用产品字阶，手机上不缩小。
- **经验沉淀**：每次调用都记下偏好、教训和有效信息，下一次先查再做。

## 适合与不适合

适合：需要从需求走到系统架构、功能清单、界面与原型，或需要为门店、场馆等现场选型设备的项目。

不适合，请改用：

- 配色、字体、图标、间距等视觉标准，海报与品牌视觉，报告、表格、Word、演示文稿和 PDF 的排版：[Luz-Design](https://github.com/luzern0414/Luz-Design)
- 后端服务、接口、数据库、支付、部署与上线：[Luz-Dev](https://github.com/luzern0414/Luz-Dev)
- 文章、文案、用户协议与隐私政策等文字：[Luz-Writing](https://github.com/luzern0414/Luz-Writing)
- 单纯的网页检索与采集：[Luz-Crawl](https://github.com/luzern0414/Luz-Crawl)

## 快速开始

1. 把本仓库放进 Agent 的技能目录（文件夹名保持 `Luz-System`）。
2. 准备依赖：Python 3.11 及以上；浏览器验收用 Playwright；调研需要 [Luz-Crawl](https://github.com/luzern0414/Luz-Crawl)；视觉标准与文件检查脚本来自 [Luz-Design](https://github.com/luzern0414/Luz-Design)。
3. 直接用中文提需求，例如：
   - “做一个健身房小程序和门店后台的系统设计和可交互原型。”
   - “我要开一家 24 小时无人健身房，软件和硬件一起出方案。”
   - “商场要统计各入口客流和在场人数，需要哪些设备、怎么接？”
   - “给这个智能客服设计对话界面和审批流程。”

产出默认写到 `D:\Codes\skill输出\Luz-System\`，可在 `scripts/new_session.py` 里修改。安装后可以先跑一次自检（`--package-only` 只检查技能包本身，不检查输出目录里的会话）：

```powershell
py -X utf8 scripts/validate_skill.py --package-only
```

## 工作方式

1. **先读规则卡**：运行 `py -X utf8 scripts/context.py <任务类型>`（`list` 列出系统设计、客户文件内容、功能列表、交互闭环、远程配置、后台列表、驾驶舱、表单、小程序、交易与营销、智能体界面、智能体输入区、智能体运行时、智能体平台配置台（平台配置台、排队与容量、定时任务、预警回传、规则与核算、智能体协同、知识库、业务流画布共 8 种）、网站、原型、交互模式与导航层级共 2 种、硬件共 26 种类型；界面的视觉层（构图与排布、组件外观、图标、配图、动效、主题、价格角标券面等效果的画法）另读 Luz-Design 的界面规则卡），读完卡上的用户偏好、相关教训、规范原文、该用的工具和必须通过的检查再动手；模板和脚本只是骨架。再查经验库里的功能模式和可复用的调研来源。
2. **建会话、记录需求**：用 `scripts/new_session.py` 建会话，在它生成的 BRIEF 里把每条需求写成带编号的需求项，注明所属模块和验收信号。
3. **模块批准**：列出模块清单，等人确认范围。（第一道人工批准）
4. **调研**：按 Luz-Crawl 的调用协议（`doctor` → `begin "主题" --new` → `experience --query` → 每条命令带 `--out`）采集同类产品与官方规范，至少 12 个网址、5 个域名；硬件调研型号、价格与渠道。
5. **系统架构**：写出角色、功能、页面、导航、动作、流程、状态、集成和追溯矩阵；每个页面写交互契约（进入方式、目标、主操作、离开方式、五类状态），对象、状态、流程闭环，由 `scripts/check_interaction.py` 检查；有智能体时写出运行时与底座（服务器推送事件、排队、重试熔断、断点续跑）。（架构批准）
6. **系统设计、视觉稿、可交互原型**：依次完成，每一步各有一次人工批准；原型在真实浏览器里逐个操作按“触发 → 反馈 → 结果 → 返回”验收，智能体原型演示七种运行状态。
7. **硬件清单**（如有）：把流程映射到设备，生成选型清单与连接图，通过文件检查后交人工批准。
8. **沉淀与发布**：每次调用至少写入或确认一条经验，并在 BRIEF 写明“采用的规则”和“本次沉淀”；之后发布唯一的最终 HTML，其余过程文件留在 `raw/`。缺规则卡、采用的规则为空或本次沉淀为空时，发布脚本拒绝发布。

文件一改，它的批准哈希就失效，下游的批准也要重新确认。脚本和模型都不能代替人批准。

## 经验沉淀

Luz-System、Luz-Design、Luz-Dev、Luz-Writing 四个技能用同一套经验沉淀：经验库是 `experience/notes.json`，每条有主题键 `key`、类别 `kind`（偏好 preference、教训 lesson、有效信息 fact）、一句话原则 `text`、可选依据 `why`、确认次数 `uses`、首次记录 `first_seen`、最近确认 `last_confirmed`，被替换过的再带一条旧说法 `previous`。开始时用 `search` 查，结束前用 `note` 写（每次调用至少写入或确认一条，键名列进 BRIEF 的“本次沉淀”），另有 `list`、`prune`、`check`（本仓库脚本 `scripts/experience.py`）。同一主题再写会替换旧说法，同一句话换了键只算再确认一次；偏好最多 60 条，教训和有效信息各 120 条，超出时先删确认最少、最久没确认的，180 天没确认的会列出来。仓库公开，手机号、邮箱、微信号、个人目录路径和密钥写不进去，检查也会拦下。

本仓库另有硬件经验库：产品按品牌与型号合并，每款只留最近 5 个价格样本；个人联系方式只存在本机不入库的文件里。

## 目录结构

```text
SKILL.md        技能入口：分工、路由、输出底线、每次调用后沉淀、工作顺序
WORKFLOW.md     各阶段的进入条件与停止条件
references/     规范网页 11 份（界面通用、后台、小程序、智能体、智能体平台配置台、网站、功能列表、交易与营销、远程配置、系统设计、硬件设计）、规则卡配置 cards.json、硬件知识、会话模板、开发交接契约
experience/     软件经验库（偏好与教训、功能与流程模式、调研来源）；hardware/ 为硬件经验库
examples/       无人健身房硬件方案示例、后台与小程序原型示例（base-prototype-next）
scripts/        规则卡（context.py）、建会话、发布、校验、经验库、硬件方案生成与客户 Excel 导出、功能清单检查（features_check.py）、测试
agents/         Agent 平台配置
```

## 七个技能的分工

| 技能 | 负责 |
|---|---|
| **Luz-Project** | 完整项目的目录、阶段、审批、客户文件与变更台账（显式调用才启用） |
| **Luz-System**（本仓库） | 系统设计：系统方案、功能清单、界面与原型、现场硬件选型 |
| [Luz-Design](https://github.com/luzern0414/Luz-Design) | 视觉标准、海报与品牌视觉、报告、表格、Word 等文件排版 |
| [Luz-Dev](https://github.com/luzern0414/Luz-Dev) | 后端、接口、数据库、部署与上线 |
| [Luz-Writing](https://github.com/luzern0414/Luz-Writing) | 文章、文案、协议等文字内容 |
| [Luz-Crawl](https://github.com/luzern0414/Luz-Crawl) | 真实浏览器检索与采集，每次业务调用的前置检索 |
| Luz-Ops | 验收测试、发布门禁、监控、备份、回滚与交付移交 |
