# 页面移植约定

这个工程把两个底座原型（网页管理后台 `admin`、小程序 `mini`）用**成熟组件库的真实组件**重做：后台用 Element Plus，小程序用 Vant（网页版，和真实小程序里的 Vant Weapp 同一套设计）。一个页面就是 `src/<端>/pages/` 下的一个 `.vue` 文件，菜单、路由、演示面板都从页面自己的 `meta` 生成，不用到别处登记。

样板页：后台 `src/admin/pages/Orders.vue`，小程序 `src/mini/pages/Home.vue`。先读它们，照着写。

## 1. 你要做什么

把旧原型里的页面用组件库重写，**保持行为**：

- 页面的编号、标题、分组、布局、布局理由、全部场景在 `legacy/pages.json`（后台页面编号对应 `window.PAGES2.<编号>`，小程序对应 `window.PAGES_MINI['<编号>']`）。
- 保留：页面编号 `id`、`label`、`group`、`layout`、`reason`，**全部旧场景（`scenes`，标签一字不改）**，业务规则与状态机，数据读写（读写 `state.db`，两个端同一份），入口到反馈到结果到返回的闭环，加载、空、错误、成功、禁用五类状态。
- 换掉：所有界面都用组件库的组件写。不照搬旧的手写 DOM。
- 可以精简：旧页面里次要的细枝末节（打印预览、批量操作之类）；精简了什么，在最后的报告里写清楚。

## 2. 页面文件的样子

```vue
<script>
export const meta = {
  id: 'orders', label: '订单', icon: 'list',        // 后台：icon 取 registry.js 的 ICONS；小程序没有 icon
  group: '交易', order: 1, roles: ['A', 'F'],       // 后台：roles（A 超级管理员，F 前台）；小程序：tab: true 的页面出现在底部标签栏，title 是导航栏标题
  layout: '横带分层', reason: '…',
  scenes: [{ id: 'nodata', label: '所选范围没有订单' }, …],   // 旧场景全部保留
}
</script>
<script setup>
// 逻辑
</script>
<template>…</template>
```

`meta` 必须写在**普通 `<script>` 块**里（不是 `<script setup>`）。文件名用大驼峰（`Orders.vue`、`OrderDetail.vue`）。

## 3. 能用的共用件（不要改，也不要复制一份）

共用代码在 `src/shared/`：

- `data.js`：`B`（演示数据的生成函数与常量，如 `B.PAY`、`B.ORDER_STATUS`、`B.NOW()`），`state.js` 的 `state.db` 是它的当前数据（商品 `products`、会员 `users`、订单 `orders`、售后 `refunds`、卡种 `cardTypes`、会员卡 `cards`、扣次 `cardLogs`、储值方案 `walletPlans`、储值流水 `walletLogs`、优惠券 `coupons`、我的券 `myCoupons`、消息 `notices`、通知模板 `templates`、权限 `perms`、角色 `roles`、账号 `accounts`、审计 `audit`、配置 `config`、素材 `files`、导出导入任务 `exportTasks`、`importTasks` 等，具体看 `data.js` 末尾的 `B.reset`）。
- `state.js`：`state`（`role`、`signedIn`、`net`、`shopStatus`、`hidden`、`scenes`、`db`），`useScene('页面编号')`（返回计算属性，等于演示面板里选的场景编号或 null），`resetDemo()`。
- `request.js`：`request(毫秒, { fail })`。网络状态是断网或不稳定时它会失败；传 `fail: new Error('文案')` 表示这个场景下这一步失败。**每个“要等服务器”的操作都用它**，失败要在界面上写原因、影响和下一步，并保留用户已输入的内容。
- `format.js`：`K`（日期）、`money(分)`、`yuan(分)`、`maskPhone`。金额都是**分**。
- `components/LzChart.vue`：图表（折线、柱、环），传数据不传 option。

后台（`src/admin/components/`）：`LzState`（加载、空、错误、无权限四种状态）、`LzPager` 加 `use-pager.js` 的 `usePager`（分页，默认每页 20，可选 10/20/50/100，页码写进地址并记住条数）、`LzKpi`（指标卡）、`LzStatusTag`（状态标签）、`LzDialog`（居中对话框，确认按钮等待请求，失败显示在对话框里且保留输入；`danger` 是破坏性操作）。

小程序（`src/mini/components/`、`src/mini/`）：`MiniState`、`MiniPrice`、`nav.js` 的 `useNav()`（`go`、`back`、`replace`、`toTab`）、`cart.js`（购物车）。

组件库的组件**不用 import**（自动按需引入）：`<el-…>`、`<van-…>`、`ElMessage`、`ElMessageBox`、`showToast`、`showDialog`、`showConfirmDialog`、`showNotify` 等直接用。图标：后台从 `@element-plus/icons-vue` 导入；小程序用 Vant 的 `icon="名字"`。

## 4. 控件一律用组件库（本工程的硬规定，检查脚本会拦）

- 按钮、输入框、选择器、开关、单选、复选、日期、表单、表格、分页、标签、徽标、菜单、导航、标签页、步骤、对话框、弹层、提示、描述列表、统计数值、时间线、空状态、骨架屏、头像、折叠面板、上传、树、级联、评分、步进器、宫格、卡片等，**全部用组件库的组件**。
- **不要写**原生的 `<button>`、`<input>`、`<select>`、`<textarea>`、`<table>`、`<dialog>`、`<nav>`，也不要用 `role="button"` 之类的 `div` 冒充控件。
- 允许自己写的只有三类：布局与组合（栅格、间距、页面骨架）；主题（颜色、圆角、字号一律用 CSS 变量，如 `var(--luz-action)`、`var(--luz-ink-2)`，不写死色值，不覆盖组件内部类名）；业务块（库里没有的块，由库的原子组件拼成）。
- 优先用库里的高阶组件：带筛选分页的表格、描述列表、统计数值、步骤条、时间线、结果页、级联与树选择、骨架屏。
- 页面底浅色，卡片白底加发丝线，状态用浅底深字的标签，不用渐变、不用深色大块（每屏至多一张品牌主卡）。

## 5. 页面要遵守的规则（来自用户偏好，逐条落实）

通用：每个操作走完“入口、反馈、结果、返回”；破坏性操作先确认；对象要有查看、编辑、删除或归档、状态变更（或写明不提供）；同一页面同一目的地只放一个入口；文字不小于 12 像素，正文、按钮、表单、表格、标题、菜单一律不小于 14，12 只给时间、标签、角标、单位与注释（`verify.py` 按角色检查）；金额靠右、等宽数字、单位写在表头；日期写年-月-日；不用斜体；中文文案简洁具体。

后台：
- 页面顶部是工具栏（筛选与操作），**不放与菜单同名的标题**；卡片不复述页面标题与时间范围。
- 表格：行高用 `size="large"`（48），表头居中，短值（状态、日期、负责人、操作）居中，长文本左对齐，金额靠右；当前视图下整列为空的列不显示；每行相同的列在筛选摘要里写一次。
- 列表分页：用 `usePager` 与 `LzPager`，默认每页 20，分页条在表格下方靠右。
- 每个列表有**默认视图**：先显示最需要处理或最有价值的子集（订单待履约、线索待跟进、工单待处理、会员有效），“全部”只是一个选项；状态标签按处理顺序排，数量为 0 的弱化。
- 详情、编辑、确认一律用 `LzDialog`（居中），**不用贴右边的抽屉**；只有影响用户、金额或不可撤销的修改才确认，行内开关与即输即查优先。
- 影响资金的改动，确认框写“改前、改后与影响”，必填原因。
- 导出的是清洗后的中文数据：中文表头、枚举译成中文、日期金额统一、去掉内部编号与空列，范围等于当前筛选，文件名写中文标题与范围。
- 角色：`state.role` 为 `F`（前台）时，没有权限的操作不显示；整页没权限用 `LzState status="forbidden"`。
- 数据驾驶舱：指标给计算后的变化、比率、排名与异常，不放长期为 0 的指标；数据少于 3 个点不画折线；按价值排序，退款等负向数据放最后。

小程序：
- 小程序字阶（Luz-Design 视觉设计规范“小程序字阶”，按微信官方字号与系统标准字号 16/17 取值）：正文、按钮、表单文字与选项、整行列表主文字 16（400）；商品名、列表项名、卡片标题、导航栏标题 16（600）；门店名、区块标题、对话框与弹层标题 18（600）；页面主标题（结果页、空状态）与详情页价格 22（700）；列表与卡片价格 16–18（600）；描述、规格、“状态 · 时间”第二行、图标下的说明、小号按钮 14；标签、角标、时间戳、划线价、货币符号与小数 12；大号数字 28 以上，每屏一个。用 `MiniPrice` 写价格。
- **字号一律写成 `var(--t16)` 这样的变量（`--t12`、`--t14`、`--t16`、`--t18`、`--t20`、`--t22`、`--t24`、`--t28`、`--t32`、`--t36`、`--t40`），不写 `14px`**：这些变量等于档位乘 `--mp-fs`（用户的微信字体大小，演示面板“微信字体大小”七档，0.94 到 1.4，最后一档是关怀模式）。Vant 组件的字号已经由 `type.generated.css` 按同一规则放大，页面里只对自己写的文字用变量；覆盖 Vant 变量时写 `var(--van-font-size-sm)` 这类引用，不写像素值。图标尺寸与间距不随字号变。
- 12 只给注释（标签、角标、时间、划线价）；按钮、表单与选项、标题、列表主文字不低于 16，描述与图标下的说明、小号按钮不低于 14（`verify.py` 按角色检查）。放在单元格 `label` 插槽里的选项和按钮会继承 14，自己写 `font-size: var(--t16)`。按钮文字不折行，按钮随文字变宽；文字放大后其余内容折行，不裁切，不出现横向滚动（`verify.py` 会在关怀模式 1.4 倍下把每页再打开一遍）。
- **文本框获得焦点时不出现蓝色选中框、光晕或粗描边**（用户 2026-11-04 严格禁止）：焦点只表现为 1 像素边框变成中性深色（主题层已把 Element Plus 的输入、选择、文本域的聚焦边框变量设为次要文字色，`base.css` 去掉了默认轮廓与点按高亮）；点击任何控件都不出现焦点框，键盘 Tab 到达才出现 2 像素中性轮廓。页面里不要写 `:focus`、`outline`、`--el-input-focus-border-color`、`--el-color-primary` 去改它。
- **头像与配色**（Luz-Design 视觉设计规范“配色只取主题”）：页面里的颜色只取主题的色阶与共用状态色，不为装饰另加色相，不给每张卡的图标块、图表系列配不同颜色；头像不用姓名首字，有照片用照片，没有就用 `src/shared/avatar.js` 的 `avatar(种子)`（种子取会员号、账号编号，同一个人始终同一张随机头像，它是图片，不计配色），未登录用线性图标。`verify.py --audit` 会对每页再跑 Luz-Design 的 `audit_palette.py --theme`，主题之外的色相与首字头像都报错。
- **浅色与深色两套主题**（用户 2026-11-04：所有前端都要有深色与浅色）：默认跟随系统，演示面板“全局”里有“外观”（跟随系统、浅色、深色）。深色是 `html.dark`，由 `theme/make-theme.mjs` 按主题库的 `dark` 映射生成（映射没有的项按“更暗的底、更亮的前景、品牌色取同色相更亮的一阶”推导）；页面里只用 `var(--luz-*)` 令牌，**不写 `#fff`、`#000` 这类字面颜色**（品牌卡上的字用 `var(--luz-on-action)`）；画图的颜色取 `LzChart`（它按 `state.dark` 换调色板），自己写图形时用 `TOKENS`、`TOKENS_DARK`。`verify.py` 会把每页的默认场景在深色下再打开一遍（`--dark 0` 跳过）。
- 自适应：手机框与演示面板按 390 × 760 的屏幕摆好，再随窗口放大（1 到 1.5 倍，`App.vue` 算出 `--phone-scale`，样式里用 `zoom`）；窗口不超过 910 时手机框就是窗口，平板宽度最宽 480。**页面里不要用 `100vh` 或按窗口量尺寸**，框内的 `100%` 与 flex 已经够用；不要自己再缩放。
- 门店营业状态读 `state.shopStatus`（`open`、`rest`、`closed`、`paused`）：不是营业中时可以浏览、不能下单，按钮换成“暂未营业”或写明原因。
- 交易界面按商用小程序做：商品卡营销信息不超过三层，规格有推荐与售罄，悬浮购物车栏写配送费与满减进度，优惠弹窗与公告弹窗有优先级与频率。
- 触摸目标不小于 40 像素（Vant 默认已满足，别自己缩小）；底部操作栏用 Vant 的 `van-submit-bar`、`van-action-bar`，不自己写 `fixed`。
- 弹层要留在手机框内：模板式的 `van-popup`、`van-dialog`、`van-action-sheet` 在原位渲染，手机框的 `transform` 会把 `fixed` 限制在框内，照常写；**函数式**的 `showToast`、`showDialog`、`showConfirmDialog`、`showNotify` 默认挂到 `body`，必须传 `teleport: '#phone-overlay'`（Vant 4.10 的 `ConfigProvider` 没有 `teleport` 属性，外壳无法代劳）。
- 游客（`state.role === 'guest'`）看到的需要登录的页面，用 `MiniState status="forbidden"` 加去登录的按钮。

## 6. 你只能改什么

- 你**只新建、只改自己负责的页面文件**（`src/<端>/pages/<页面>.vue`），需要时可以在自己页面的 `<style scoped>` 里写样式。
- **不要改**：`src/shared/`、`src/*/components/`、`src/*/registry.js`、`router.js`、`App.vue`、`main.js`、`*.css`、`theme/`、`build.mjs`、`vite.config.mjs`、`scripts/`、`package.json`。需要共用件有改动（缺一个组件、缺图标、缺共用函数），不要自己动，写进最后的报告里。
- **不要运行 `npm install`**，不要引入新的依赖。
- 订单、会员卡、储值、券这些数据只通过 `state.db` 读写，保持两个端的数字对得上（订单金额等于商品小计减优惠，退款不超过实付，卡的剩余次数等于总次数减扣次记录，余额不为负）。

## 7. 构建与验证

```powershell
cd examples/base-prototype-next
# 构建到你自己的目录（不要用默认的输出位置，别人也在构建）
npm ci                                            # 仅在缺开发依赖时恢复锁定版本
node build.mjs admin --out <你的私有目录>          # 或 mini
# 逐页逐场景验证：控制台零错误、没有横向滚动、页面不空；加 --audit 再核对控件来源与文字规则
py -X utf8 scripts/verify.py admin --html <你的私有目录>\admin.html --only <你的页面编号,…> --audit
# 看效果：--shots <目录> 会存每页 1440 和 390 宽的截图，用 Read 工具看
```

`--audit` 会调用 Luz-Design 的 `audit_rendered.py --library --min-font 12`：手写的控件、字号低于 12 像素（产品界面的下限，正文仍用 14）、字重不在 400/600/700、对比度不足、触摸目标过小都会被报出来，**全部要改到零**。库自己样式表里的 `will-change`、`transition: all`（选择器以 `.el-`、`.van-` 开头）页面改不了，脚本已过滤；组件库默认值带来的问题（12/13 像素文字、字重 500、按钮高度、字体变量、标签对比度）已在共用主题里统一修好，不要在页面里用 `:deep` 或覆盖 `--el-*`、`--van-*` 去改。

`verify.py` 除了逐场景检查控制台、横向滚动（含页面区域内部）、页面是否为空，还会检查**小字**：控件、字段标签、表格单元格、标题与菜单里小于 14 像素的文字会报错（注释、标签、角标、单位可以是 12，页面里用 `.small`、`small` 或库的标签类）。每页的默认场景还会在 768、1024、1920 宽各打开一次（`--sweep`，不要的话传 `--sweep ""`），检查自适应时没有横向滚动。如果审计没能运行也会报错，不会静默通过。数字是否对得上用 `py -X utf8 scripts/check_data.py <admin|mini> --html <文件>` 核对：逐页访问后检查订单金额、退款、卡次数与扣次记录、余额。一个页面做完要在 1440 和 390 两个宽度看过截图，再逐个场景走一遍（`verify.py` 已经走了每个场景，但要自己看一两个场景的截图确认文案和状态正确）。
