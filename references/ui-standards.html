界面通用规范

适用范围

适用于所有产品界面：网页管理后台、小程序、智能体、网站，以及交付网页里的系统功能列表与可交互原型。本页给出各端共用的标准，按层次从上到下排列：设计架构、功能架构、信息架构与导航、页面内容与优先级、组件、视觉交接、文案。每一层末尾的“分端细则”列出四个端在这一层的差异，完整细则写在各端规范的同名层里。

视觉与排版基础（配色、字体字号、图标、圆角阴影、动效、间距、文字纪律）由视觉技能的视觉设计规范统一规定，本页第六层不决定任何视觉值；四个分端规范只能在本页之上收紧，不能放宽。本页规定的是底线和判断方法，不是模板：主色、组件组合与版式结构由每一次的内容推导。

工作流程

  1. 确定产出属于哪个端（可以多端），找到对应的分端规范。
  2. 设计前用浏览器采集技能（Luz-Crawl）查视觉设计规范“组件与组件库”登记的组件库中对应组件的规范页（见第五层“参考组件库”），记录参考了哪一家的哪个组件。
  3. 按层设计：第一层定页面类型与设计理念，第二层给每个功能分类并定入口与内容来源，第三层定导航与返回，第四层定页面内容与优先级，第五层定组件，第六层把视觉交给视觉设计规范，第七层定文案。
  4. 每一层先读本页的通用规则，再读分端规范的同名层；分端规范没有提到的，按本页执行。
  5. 对每个可见元素做“删除测试”，再按“问题的同类判断”逐类自检，不只核对例子。
  6. 用浏览器在各端规定的宽度逐页验证，截图核对后交人工批准。

一、设计架构

设计原则

  • 用户任务优先：先回答“用户来这里完成什么”，再决定页面、组件和视觉；任何元素都要能说出它帮助用户认出什么或决定什么。
  • 核心在前：核心任务占据最显眼、最稳定的位置，状态与信息其次，营销靠后，辅助功能收进二级页（见第二层“入口与内容分层”）。
  • 一个目的一个入口：同一页面同一目的地只有一个入口，同一信息只说一次。
  • 一致可预期：同类元素同名称、同行为（外观一致见视觉设计规范“同类元素外观一致”）；同一对象在各端用同一个名字和同一个图形。
  • 系统状态可见、操作闭环：每个操作有入口、反馈、结果与返回，每个失败有原因和下一步，危险操作可确认、可撤销或可追溯（第二层“功能闭环”、第三层“页面交互契约”、第五层“操作反馈”）。
  • 扁平为主：层次不靠装饰（见视觉设计规范“扁平线性风格”“层级与立体感”）。
  • 依据可查：规则与交互取自公开标准与调研证据，不凭感觉；每条判断能指出出处。
  • 重要的先显示，没有信息量的删掉：界面先显示“现在最需要处理、最有价值”的内容，其余内容退后但可达；同一信息在一屏内只出现一次；没有信息量的元素（全空的列、长期为零的指标、只有一个点的图表、与导航重复的标题）删除或收起。按类别判断，不只修示例（见本页“问题的同类判断”）。

设计判断顺序

  1. 第一眼看什么：读者拿到产出后最先需要的信息，决定主标题和第一个区块。
  2. 内容是什么形状：结论、对比、流程、清单、数据还是叙述；形状决定结构，不是先选样式再塞内容。
  3. 哪些可以删：删掉后读者决策不受影响的信息一律删除，包括过程信息、自我介绍和装饰。
  4. 主色与字阶：不在本页选，按视觉设计规范“主题色系统”“字阶：按产品类型各用一套”确定。

设计流程

  1. 需求编号 → 模块表单与人工批准 → 浏览器调研 → 系统架构与人工批准（见系统设计规范）。
  2. 设计前查参考组件库：用浏览器采集技能（Luz-Crawl）打开视觉设计规范“组件与组件库”登记的组件库规范页与组件页，查清该组件的默认值、尺寸、状态与交互，在设计说明里写明参考了哪一家的哪个组件；视觉以视觉设计规范为准，不照搬组件库的风格。
  3. 按本页从第一层到第七层逐层设计：先定端与页面类型，再定功能分类与入口，再定导航，再定页面内容与组件，视觉按第六层交给视觉设计规范，最后定文案。上一层没定，不做下一层；页面由组件组合而成（原子设计方法：原子、分子、组织、模板、页面由小到大组合）。
  4. 每一层先套用本页的通用规则，再套用所在端规范的同名层；两处冲突时以分端规范为准，分端规范只能收紧，不能放宽通用规则。
  5. 视觉方向与视觉稿按视觉设计规范，可交互原型用浏览器逐页验证，交付前按“问题的同类判断”逐类自检。

二、功能架构

入口与内容分层

先判断每个功能属于哪一类，再决定它放在哪里、能不能隐藏；各类别的外观注意力分配见视觉设计规范“层级、分隔与装饰”。判断用四个问题：用户打开这个产品主要来完成什么；这个功能多久用一次；去掉它产品还成立吗；它有没有截止时间、库存或人群限制。

类别判断特征放在哪里配置例子（不限于）
核心功能产品成立的主任务，高频、刚需，去掉它产品就不成立底部标签或首屏固定位置；在自己的标签里排第一固定显示，装修不能隐藏，只能调整顺序健身房的购卡与续卡、刷脸入场、门店卡；订餐的点餐与订单；后台的数据驾驶舱
状态与信息帮助用户做决定的实时信息或个人状态，不需要操作，或只需一个查看动作紧跟核心之后；个人状态归它所属的标签用数字、标记和小图表表达；可配置实时客流、门店公告、会员卡余量与到期、订单状态

一个业务只有一个入口
  • 同一页面内，同一个目的地（同一页面加同一参数）只有一个可点击入口；宫格、轮播、卡片、按钮不同时指向同一功能。把入口放在用户预期的显眼位置，比在多处重复当作“保险”更有效；重复的入口会分散注意力，用户还要判断它们是否通向同一处。长页面的首要入口滚出视区后可以由吸顶栏承接，但同一时刻只出现一个。
  • 核心任务已有固定入口（底部标签、侧栏菜单、顶部导航）时，其他位置不再放它的入口；整张卡片可点击时，卡片内不再放指向同一目的地的按钮。
  • 营销活动只占一个位置：轮播图、宫格入口、活动卡片、公告栏不同时出现同一个活动。选定一种载体后，其余载体不再提它；不用轮播堆叠多个活动，轮播第三帧之后几乎没有人看。
  • 宫格（金刚区）只用来分发多个并列的高频核心业务；底部标签已覆盖核心功能、首页模块已承载营销时不设宫格。宫格里不放本页已有模块的业务、其他标签的功能，也不放账户与个人资产类（会员、收藏、优惠券钱包、地址）和全局上下文类（门店、配送方式）；入口少而重要，凑不满一屏就不凑，不为了好看补低频入口。
  • 汇总卡只做汇总：门店卡通过一行“门店详情”进入详情，详情已有的相册、设施不在首页另设入口；“我的订单”只有一个“全部订单”入口加按状态入口，不再另设“全部”格子。
  • 修复动作就近且唯一：状态有问题时，把修复按钮放在出问题的状态上（例如“人脸 未录入 · 去录入”）；失败结果的提示只写原因和怎么办，不再重复同一个按钮。
  • 跨标签：功能只在一个底部标签有家（见小程序设计规范“导航、页面栈与返回”）；其他标签的空状态、结果页只能打开承载这件事的二级页，不重复放一级入口，也不显示另一个标签的计数格子（例如“我的”里不放入场次数、中奖次数）。
不重复表达
  • 一张卡片里每条信息只说一次：标题、副标题、标签、角标、按钮、说明之间不互相复述。例如副标题写“30 天不限次入场”，标签就不再写“不限次”；划线原价已表达优惠，角标不再写“省 398”。
  • 状态只用一种表达：卡片上的状态标记已写“已过期”，就不再加一条“会员卡已过期，请续卡”的提示条；临期、余量不足并入同一个状态标记（“3 天后到期”“仅剩 3 次”），续卡按钮只有一个。
  • 同一页面的说明只出现一次，公告、标签、副标题不复述下方模块的内容：详情页“权益”已展开标签，标题下不再列标签；“使用规则”不复述副标题里的有效期；公告栏只写门店运营消息，不复述页面上已有的营销活动。
  • 模块标题与内容不同义：标题叫“新人礼券”，券名不再以“新人”开头；标题叫“每日抽奖”，副文案只写剩余次数与最高奖，不写口号，也不把奖品再列成一排标签。

验收方法：对每个页面列出全部可点击元素的“目的地 + 参数”，有重复即退回；对每张卡片列出全部文字，含义相同的只保留一处；原型的自动测试对每个一级页和详情页执行这两项检查。

功能闭环

每个操作都是一个闭环：入口 → 反馈 → 结果 → 返回。设计时对每个页面列出全部功能与按钮，先按“一个动作一个按钮”去重，再逐个检查四段是否齐全，最后核对对象、状态与流程。

一个动作一个按钮
  • 同一页面同一动作只有一个可见入口：同一个动作编号在一个页面只出现一次；列表每行的逐行操作除外（每行一个，只作用于该行）。
  • 不同按钮不做同一件事：两个按钮的结果相同（同一功能、同一目标页或同一状态变化）时只留一个；“新建”“发送并新建”“顶栏新建”指向同一对象时合并为一个入口，来源与格式做成这个入口里的选项（“导出”只有一个按钮，格式在浮层里选）。
  • 文字相同即同一动作：同一文字只对应一个动作，同一动作在各页用同一文字；“我来处理”与“交给人工”这类同义按钮只留一个。
  • 导航项与按钮通向同一页时它们就是同一个元素（架构里用导航编号把动作和导航关联起来），否则只留一个；整张卡片可点时，卡片标题与卡片算一个入口。
  • 同一状态变化只用一种控件：上下架、启用停用在“列表行内开关”和“详情页按钮”之间只选一处；必须两处都有时用同一文字和同一确认。

流程成功终点（落在哪个页面或状态）与每种失败的恢复入口只画成功路径；超时后不知道是否已成功就允许重复提交
审批与确认批准、修改、拒绝、确认后各去哪里；不同按钮的结果必须不同“拒绝”和“修改”都回到同一页且做同一件事
异步操作进行中、成功、失败（原因与重试）、空四种结果都有呈现导出只有转圈；搜索没有结果时一片空白
  • 破坏性操作（删除、撤销、停用、重置、下架、退款）先确认：标题写对象，正文写后果与能否恢复，按钮写动作，不设默认确定；能撤销的给撤销，不能撤销的在确认里写明。
  • 列表空状态写对象和一个行动（“还没有会议 · 开始录音”），不只写“暂无数据”。
  • 验收方法：在原型里逐个操作走一遍“触发 → 反馈 → 结果 → 返回”，任何一步断开即不通过；架构里的写法见系统设计规范“架构的交互字段”，由检查脚本 check_interaction.py（validate_session.py 调用）核对。

依据：尼尔森诺曼集团“用户控制与自由”（明确的紧急出口，返回只退一步，支持撤销）与“确认对话框”（只为严重后果确认，复述对象与后果，按钮写结果，不设默认“是”）；尼尔森诺曼集团“同一链接在同一页出现两次”（重复入口增加选择成本）；蚂蚁设计体系“设计价值观”（为每个行为给恰当、即时的反馈）。

内容来源与维护闭环

架构中为前台（小程序、网站、智能体）的每一处内容和文字写出来源与维护入口，形成一张内容来源表：内容 → 来源 → 维护入口 → 维护动作 → 是否在后台展示。

来源例子谁维护、怎么生效后台展示
后台配置门店资料、照片、公告、须知、套餐、券、奖品、模块顺序与显隐、展示开关、页面上的提示与说明文字；经营规则（退款手续费、储值扣减顺序、退券策略、补卡费、起送价、配送费）与商品的购买规则运营在后台维护，保存即生效；影响资金的经营规则改前重新验证身份并写原因展示
后端存储、不在后台展示通用控件词、系统级提示、法规固定文字、技术性展示配置开发经数据种子维护，走代码评审不展示
运行参数上传上限、超时、轮询间隔、功能开关、最低可用版本配置文件，服务端热加载，见远程配置规范不展示

  • 前台的文字提示与数据展示尽量由后端下发：页面上确需的每处文字（提示、空状态、引导、须知、规则说明、弹窗与确认文字、营销副文案）有一个文案键，后端存当前文案，安装包只带兜底默认值；模块顺序、显示隐藏与展示开关同样由后端下发。前端只写版面，不写死文字与运营内容。
  • 改文案与展示无需发版：后台保存后，小程序下一次显示该页即换成新内容（小程序设计规范“文案与展示下发”）。
  • 后台配置的内容必须在后台有完整维护动作：列表可新增、编辑、删除或停用、排序、显示与隐藏；图片可上传、删除、设为封面、改说明、排序；文字可编辑；状态用开关。
  • 小程序不写死运营内容，同一内容只有一份数据；营销内容（新人礼券、抽奖奖品）引用后台的优惠券与奖品，不另存副本。
  • 功能列表为每个后台维护动作列出功能编号；原型测试逐项在后台修改，再到小程序对应位置核对。

权限与角色

  • 每个页面与动作写出可见角色和可操作角色；看不到的功能不出现，看得到但不能操作的功能禁用并说明原因。
  • 无权限是一种页面状态：写清缺少什么权限、找谁开通，不显示空白或报错代码。
  • 变更、审批、金额与个人信息相关的操作进入审计记录；界面只表达授权结果，授权由服务端执行。

个人信息与隐私

个人信息的收集、使用、撤回在产品里怎样呈现，是设计问题，不能留到实现阶段补。依据：《中华人民共和国个人信息保护法》（2021 年 11 月 1 日起施行）和国家标准 GB/T 35273-2020（现行版，修订稿未发布，引用前核对当前版本）；法律条文的写作交文字技能，律师审核，实现交开发技能。

  • 最小必要：只收集实现当前功能直接需要的信息，每个收集点写明用途；拒绝提供非必要信息不影响基本功能和其余服务（个人信息保护法第 16 条，国标 5.2）。
  • 用户主动：用户用到功能时才请求授权，不在启动时一次性申请多项权限；授权靠用户自己的肯定动作（点击、勾选），不预先勾选，不把多项授权捆成一个同意，不反复追问（国标 5.3）。
  • 敏感信息单独同意：人脸等生物识别、医疗健康、金融账户、行踪轨迹和不满 14 周岁未成年人的个人信息，单独告知处理目的、必要性和对个人权益的影响，并取得单独同意；不满 14 周岁的须取得监护人同意（个人信息保护法第 28 至 31 条，国标 5.4）。生物识别信息原则上不保存原始图像（国标 6.3）。
  • 告知清楚：隐私政策的入口常驻（登录页和“我的”），一两步可达，涉及敏感信息的内容显著标出，用易懂的语言；向第三方提供个人信息要单独同意（个人信息保护法第 17 条、第 23 条）。
  • 撤回与权利：撤回同意和同意一样便捷；用户能查阅、复制、更正、删除自己的信息，页面上有受理入口；账号注销的方法简便，不加额外条件（个人信息保护法第 15 条、第 44 至 47 条、第 50 条，国标 8.4、8.5）。账号注销的要求来自国标，不是个人信息保护法的条文。
  • 个性化与自动化决策：个性化展示要和非个性化内容区分，并提供关闭方式；不得在交易价格等条件上对个人实行不合理的差别待遇（个人信息保护法第 24 条，国标 7.5）。
  • 采集设备：公共场所的图像采集和身份识别设备要设置显著的提示标识（个人信息保护法第 26 条）；人脸识别的另行规定见硬件设计规范。
  • 评估：处理敏感个人信息、利用个人信息做自动化决策等，事前要做个人信息保护影响评估并记录（个人信息保护法第 55 条）；这类功能在系统架构的“个人信息与隐私”一项里标出，并列为待办。

三、信息架构与导航

信息架构

  • 导航层级不超过 3 级；后台一级菜单 5–9 项，超出时按业务域分组；小程序底部标签 2–5 个。
  • 菜单与页面名用 2–6 字的业务名词，例如“订单”“退款审核”；同一对象在菜单、标题、面包屑、按钮中叫同一个名字。
  • 每页一个主任务。页面类型只有：列表、详情、表单、看板或工作台、设置、结果。一个页面不混合两种主任务。
  • 每个页面都能回答：谁使用、做什么决定、从哪里来、完成后去哪里、失败后怎么恢复。
  • 深层页面不伪装成标签页；弹层只承载短决策，超过一屏的内容改为独立页面。
  • 页面功能隔离：首页只放品牌或门店（核心）、实时信息与营销，已有专属标签的核心功能与商品不在首页重复；每个底部标签只承载一类目的；个人数据（订单、使用记录、持有的优惠券、账号与隐私）归“我的”，已有专属标签的对象（例如会员卡、刷脸入场）只在自己的标签中出现。
  • 一个功能只有一个家：每个功能只在一个一级页面作为主入口；其他一级页面不重复放它的入口或状态卡。检查方法：列出每个一级页面上的入口，任何入口的目标属于另一个底部标签，即为重复。
  • 信息完整：门店页有名称、评分、营业状态与时间、地址与距离、电话与导航、设施、环境照片；商品详情有封面轮播、权益、有效期、适用门店、价格与原价、销量、使用规则、购买须知。

导航与返回

  • 任何页面都回答三个问题：我在哪、能去哪、怎么回去。当前位置在导航里高亮；需要显示页面名时（详情页、无导航的端）与导航名一致。
  • 一级导航只放核心任务和稳定的业务域；临时活动不进一级导航。
  • 返回回到打开当前页的来源，流程完成回到发起处；打开新页面与浮层不丢失原页面的筛选、滚动与输入。
  • 深链接可直接打开：从分享、搜索、通知进入任意页面时，页面能独立成立，并能回到上一级或首页。

多级目录与导航层级

层级的定义：用户到达页面必须经过的、可点击的导航层数，含一级。分组标题不算层级；页面内的标签页、分段控件和锚点不算层级，但标签页里再放标签页算一层。上限 3 级（第三层“信息架构”），先按条目多少选方案，条目装得下就不加层。

可见页面数方案要点
不超过 7一级平铺底部标签、顶部导航或侧栏平铺，不分组、不折叠
8–30一级分组加二级侧栏按业务域分组（分组标题只是标题，不是层级）；有子项的一级项折叠，展开最长分支不超过一屏
31–60顶部业务域加侧栏二、三级顶部放 5–7 个业务域，侧栏只显示当前域的二、三级；加全局搜索
超过 60，或需要第 4 级不加第 4 级先重构信息架构：把“类型”变成筛选项，把子类变成详情页内的标签页或分区，合并低频页；再加全局搜索、命令面板与最近访问直达
  • 当前位置：当前页的项高亮，它的各级祖先项也要标出所在分支，但与当前项有区别；同一时刻只有一个“当前项”。折叠成图标栏时，祖先的一级图标仍标出所在分支（高亮的样子见视觉设计规范“导航与多级目录的数值”）。
  • 展开收起：打开页面自动展开当前项所在分支并滚到可见，其余分支收起；有子项的节点只负责展开收起，不兼作页面，需要概览页时把“概览”作为子项第一项；展开状态在本次会话内保持。展开收起的动画与箭头见视觉设计规范“导航与多级目录的数值”。
  • 图标：只有一级项带图标，二、三级项不放图标；一级项缺图标仍算缺。图标栏状态下二级项以悬浮菜单显示，菜单内带文字；图标尺寸与层级的缩进、字重见视觉设计规范“导航与多级目录的数值”。
  • 长名称：菜单名 2–6 字；放不下时省略，聚焦与悬停显示完整名称（Esc 可关闭提示）；省略的版式见视觉设计规范“各端视觉参数”。
  • 顶部加侧栏：顶部放业务域，侧栏放该域的子级；切换业务域时侧栏整体替换，并回到该域上次停留的页面；同一入口不在两处出现（第一层“一个目的一个入口”）。
  • 面包屑：层级达到三级、从搜索或深链接进入、或在详情页时才需要；一级页不放；中间项可点，最后一项是当前页不可点；名称与菜单一致；层级过深时的折叠见视觉设计规范“导航与多级目录的数值”。
  • 搜索与直达：页面总数超过 30 或存在第三级时提供全局搜索（Ctrl+K 或 ⌘+K），结果带层级路径，键盘可全程操作。
  • 键盘：目录是一棵树，上下方向键在可见项间移动，右方向键展开或进入子项，左方向键收起或回到父项，Enter 打开，Home 与 End 到首尾；展开状态用 aria-expanded，当前项用 aria-current="page"。
  • 移动端抽屉：侧栏在窄屏进左侧抽屉（宽度见视觉设计规范“导航与多级目录的数值”），带遮罩；打开时焦点留在抽屉内，选择页面后自动关闭，遮罩、Esc 与系统返回都能关；抽屉里的多级用折叠项，同一时刻只展开一个分支。小程序不用抽屉，用页面栈（小程序设计规范“分类与多级目录”）。
  • 树形选择器：节点超过 10 个时带搜索；默认折叠，已选节点所在分支自动展开；搜索时展开所有命中节点的祖先并高亮命中字；多选时父节点三态（全选、半选、未选），勾选父节点即选中全部子孙，触发器显示“已选 N 项”；层级同样不超过 3 级；大数据按层懒加载，加载中显示行内加载态。
  • 检查方法：画出导航树数层数；展开最长分支量高度是否超过一屏；逐个叶子页用深链接打开，核对祖先高亮、面包屑与菜单同名；只用键盘走完整棵树。

页面交互契约

架构里每个页面写一行交互契约，六项缺一项即退回设计；字段写法见系统设计规范“架构的交互字段”。

五类状态加载、空、错误、成功、禁用各自的表现与文案；确不适用写“不适用”和理由空：还没有订单 · 去点餐
  • 无孤岛页：每个页面至少有一个入口（导航、动作或其他页面的完成去向）；只有标签根页、登录页与外部链接页可以没有站内入口。
  • 无死角页：每个非一级页面都有返回或完成出口并写明回到哪里；浮层与全屏页有明显的关闭方式（右上角关闭、取消或下滑）；结果页“完成”回到发起处。
  • 返回只退一步：返回回到上一页，不等于取消整个流程；多步表单返回上一步不丢已填内容。
  • 跨标签不切标签：从一个标签打开属于另一个标签的详情时，在当前标签的页面栈里打开，返回回到来源（与小程序设计规范“导航、页面栈与返回”一致）。

页头与品牌标识

  • 后台与网站的页头放品牌标识：一个图形图标加系统名或品牌名（后台在顶栏左侧，没有顶栏时在侧栏顶部；网站在顶部导航左侧）。图标与浏览器标签页图标是同一个图案，同一系统的每个页面都一样；不用文字缩写方块、首字母或空白占位代替。
  • 图案的选择与绘制规范见视觉设计规范“网页图标与品牌标识”。
  • 每个交付的网页（系统设计、视觉稿、原型、硬件方案）都带浏览器标签页图标 <link rel="icon">，内联 SVG，不依赖外部文件。模板里的 {{TAB_ICON}} 与 {{BRAND_MARK}} 由 new_session.py 按系统名选图案与主题填入；手工页面用 py -X utf8 scripts/new_session.py icon 系统名 取得两段代码。
  • 小程序首页的品牌或门店区承载品牌，不另加页头标识；阅读页（报告、方案）只需要标签页图标。

标题不重复导航

  • 导航已高亮当前项（侧栏的“会员管理”、底部标签的“订单”）时，页面顶部不再放同名的大标题；顶部区域留给本页的操作（新建、导出）与筛选。需要层级时用面包屑，只在两级以上的详情或子页出现。
  • 导航分组名不与组内唯一一项同名（例如分组“概览”下只有“概览”）；组内只有一项时取消分组。
  • 卡片标题不复述页面标题；卡片副标题不重复页面已选的时间范围，更不能写与之矛盾的范围（页面选了“近 30 天”，卡片里写“全部时间”即为错误）。

列表的默认视图

每个列表在设计时写明“默认视图”：默认状态筛选、默认时间范围、默认排序，以及为什么。默认选中最需要处理或最有价值的子集，“全部”放在可选项里。

  • 状态标签的顺序等于处理顺序：先待处理，再进行中，再完成，最后关闭、取消、无效；终态排在最后或收进“更多”。
  • 数量为 0 的状态标签：数字用弱化色，不抢视觉；同一组里全为 0 的终态可以收进“更多”。
  • 默认排序：待处理列表按紧急程度（逾期优先、截止时间近的优先）；结果类列表按时间倒序。
  • 默认视图与顶部统计不重复表达同一组数字：要么“状态标签带数量”，要么“可点击的统计卡充当筛选”，二选一，不同时出现。
  • 默认值与用户改过的筛选在地址栏参数或会话中保持，从详情返回列表时不丢失。
  • 各类业务对象的默认视图见各端规范，例如网页管理后台设计规范“列表的默认视图”。

同一组里功能相同的元素是“同类元素”：宫格入口、服务格、资产格、商品卡、列表行、按钮组、标签页、筛选项、选项按钮、指标卡、配置面板的选项、表单字段。用户靠一致性判断它们是同一类东西，任何一项与众不同都会被读成“特殊”或“出错”。

  • 先写清驾驶舱类型：运营型（实时、要处理的事：待办、异常、超时）还是分析型（趋势、转化、对比）；类型决定第一屏放什么。
  • 指标优先展示计算分析后的结果：环比与同比变化、转化率、达成率、人均与单均、排名、异常提醒，而不是原始累计数。
  • 长期不变或长期为 0 的指标（“已成交 0”“失败任务 0”）不占主位：为 0 且无需处理时合并成一行状态说明（“暂无异常”），有值时再以醒目方式出现。

  • 按价值排序：重要和变化大的在前，退款等负向数据与变化小的在后（后台的具体顺序见网页管理后台设计规范“数据驾驶舱”）。

  • 架构里每个页面写“布局：哪一种；理由：主角是什么”。

  • 标签写法分三种。一、开关：标签永远是设置项名称（“自动续费”），开启时说明它做什么，不写成“开启自动续费”“关闭自动续费”来回换。二、状态本身要被看见的二态按钮（收藏、关注、点赞、静音）：按钮名称固定为动作对象（“收藏”），用 aria-pressed 表示是否已按下（外观见视觉设计规范“界面组件的外观”中的“切换控件”），不把名称换成“已收藏”“取消收藏”。三、动作互换的二态按钮（播放与暂停、展开与收起、发送与停止）：名称写“点一下会发生的事”（正在播放时叫“暂停”），图标也画目标动作，不用 aria-pressed。同一产品同类按钮只用一种写法。
  • 位置与尺寸：切换前后控件的位置不动、宽高不变，邻近元素不位移；按钮的两种标签取较长者定最小宽度；点击反馈在 100 毫秒内出现；过渡时长、缓动与滑动的做法见视觉设计规范“卡片与切换控件的动效”。
  • 禁用态：保留位置，用 aria-disabled 并保持可聚焦；悬停与聚焦时说明原因（“有附件正在上传”）；不因禁用而移除控件，避免界面跳动；禁用的外观见视觉设计规范“界面组件的外观”中的“切换控件”。
  • 乐观更新与回滚：开关属于设置，不做乐观更新，点击后滑块进入加载态、忽略重复点击，服务端成功才切换，失败保持原状态并写原因（与本页“常用控件做法”的开关一致）；收藏、关注、点赞这类低风险、可撤销、只影响自己的二态按钮做乐观更新，立即切换，失败时回滚并轻提示原因。影响金额、库存、上线或他人的切换一律不乐观。快速连点只提交最后一次状态；刷新或回滚后以服务端返回值为准。
  • 状态保留：标签页与分段控件切换后，每个视图保留各自的筛选、排序与滚动位置；刷新时由地址恢复当前项；切换不清空其他控件已填的内容。

  • 检查方法：列出本页全部“两态”控件，逐个核对：控件选对、标签写法属于上面三种之一、切换前后位置与尺寸不变、禁用写原因、失败回滚、连点只提交一次；原型用 check_interaction.py 核对开关带 aria-checked、aria-pressed 按钮不改名。
错误正确
收藏按钮点一下文字变成“取消收藏”，宽度跟着变，旁边的分享按钮被推走按钮名称固定为“收藏”，用 aria-pressed 表示状态，宽度不变
开关旁写“开启自动续费”，关闭后变成“关闭自动续费”标签固定为“自动续费”，状态由开关本身表达
上下架开关乐观切换，失败后没人知道开关进入加载态，成功才切换，失败保持原状态并写原因
发送键输入框为空时直接隐藏，有内容才出现，输入框宽度随之跳动槽位固定，置灰并说明原因，或换成语音入口
用标签页做“列表与卡片”视图切换，切换后筛选条件丢失用分段控件切换同一份数据的视图，筛选保留

表单与输入

  • 标签永远可见，不用占位文字代替标签；必填统一标记；字段只留短标签，不在输入框下加说明句。
  • 一列排布，按填写顺序；相关字段成组；字段越少越好，可推断的值预填。
  • 失焦时校验该字段，错误写在字段下方并说明怎么改；提交时汇总校验并聚焦第一个错误；提交失败保留已填内容。
  • 选择项少于 5 个用单选或分段，多于 5 个用下拉或搜索；开关只用于立即生效的二元状态；区间与比例用滑块并实时显示数值。
  • 输入框的圆角与高度见视觉设计规范“界面组件的外观”中的“输入框与登录页”“各端视觉参数”。
  • 图片与文件上传：用户自己无法改小的文件（系统相机拍的照片、相册原图）不限制大小，也不提示“图片过大”：前端只接收并上传原图，压缩统一由后台完成；用户能换一个文件的（合同、文档、表格）才限制大小，并在选文件前写明格式与上限。上传中显示进度，失败可重试，已选的图保留。

列表与表格

  • 表格的对齐、缩进、表头与行高的写法见视觉设计规范“表格对齐与缩进”，后台的列类型表见网页管理后台设计规范“表格与列表”。
  • 同列精度与格式一致；个别空值用“—”，整列为空时隐藏该列（见第四层“精简”）。
  • 列表工具按需齐全：搜索即输即查、筛选显示数量、排序、分页或加载更多、批量操作、导出。
  • 加载用骨架，空列表给一句话和一个行动，失败给原因和重试。

列表变更与动画

动画只用于用户能把变化同自己的操作联系起来的时刻：新增、删除、重排、展开。重新加载、刷新、切换筛选和翻页之后的整体重绘不播进入动画（见视觉设计规范“问题的同类判断”中的“动效失序”）。时长、缓动、延迟、位移和降级的数值见视觉设计规范“动效细则”中的“列表变更的动效”。

事件做法不要
首屏加载加载超过 300 毫秒才出骨架屏，出现后至少停留 500 毫秒（见视觉设计规范“稳定显示”），骨架行数与行高同真实行；内容到达后整体替换；虚拟列表和长列表滚动进入不做进入动画逐行入场；骨架与真实内容高度不同造成跳动
新增一项新项展开出现，下方各项平滑让位，新行短暂标出下方内容突然跳位
删除一项消失与下方上移同时进行；5 秒内提供撤销，撤销时回到原位先消失再上移（两段跳动）
重排（排序、拖拽放下）各项平滑移到新位置，拖动中的项有明显标记重排时整行淡出再淡入
筛选、排序、翻页换整表保留旧内容并显示加载态，新内容到达后整体替换先清空再加载造成闪白
加载更多（追加到末尾）追加项出现，已有内容不位移，滚动位置不变；一次追加很多项时不逐项依次入场追加后滚动位置跳动；几十项依次入场
流式追加（智能体回复）不做进入动画，只扩展文本；步骤卡出现不挤动已有内容逐字淡入、打字机音效、闪烁光标
实时新增（推送、新消息）用户不在新内容位置时，不插入视口、不改变滚动位置；顶部或底部出现“有 N 条新内容”条，点击后插入并滚动到位把用户正在看的内容推走
  • 避免布局抖动：图片写宽高或 aspect-ratio，卡片、骨架、图表先占好尺寸；不在已显示内容的上方插入新内容，必须插入时让浏览器滚动锚定生效（overflow-anchor 保持默认）或手动补偿 scrollTop；动画的实现写法见视觉设计规范“动效细则”中的“性能与写法”。
  • 位置保护：从详情返回列表时回到离开时的位置与已加载的批次；同一会话内保存滚动位置。
  • 空与失败：空列表给一句话和一个行动；加载更多失败在底部写“加载失败，点击重试”，不清空已加载内容（本页“分页与加载更多”、小程序设计规范“列表加载”）。
  • 减少动态效果：系统开启后，去掉位移与高度动画，新增项直接出现，新行改为静态标出（时长见视觉设计规范“列表变更的动效”）；“有 N 条新内容”条保留。
  • 检查方法：对新增、删除、重排、加载更多、实时新增各录一段屏，核对周围内容是否跳位、滚动位置是否变化；在开发者工具里开启“减少动态效果”再测；原型用 check_interaction.py 核对每个过渡或动画都有 prefers-reduced-motion 分支、没有 transition: all、不对宽高外边距做过渡。

分页与加载更多

  • 后台与网站里数据可能超过一页的列表都分页：默认每页 20 条，可选 10、20、50、100 条/页，分页条在表格下方靠右；位置与顺序、地址参数、记住每页条数、翻页反馈与导出范围的逐项细则和依据见网页管理后台设计规范“分页”。
  • 小程序与移动端不用页码：滚动到底自动加载下一批（每批 20 条），细则见小程序设计规范“列表加载”。
  • 原型里的分页能真实切换页码与每页条数。

筛选

  • 常用筛选外露最多 4 个（搜索框加 2–3 个最常用条件），其余收进“更多筛选”或表头筛选；时间的快捷范围与自定义日期合并为一个控件；已生效的筛选以可移除的标签显示并可“清空”。
  • 默认值有意义（见第三层“列表的默认视图”），默认值与用户的选择写进地址栏参数，返回列表时不丢失；数量为 0 的选项与状态标签弱化或排到最后。后台的细则见网页管理后台设计规范“筛选”。

导出

  • 导出的是给人看的数据，不是数据库原表：中文业务表头、枚举译成中文、统一日期与金额、去掉内部编号与空列、一格一个事实；范围等于当前筛选结果，文件名写中文标题与范围；只在确有离线使用需求的列表放导出。清洗规则、文件名与版式（文件设计规范的表格文件规则）的逐项写法见网页管理后台设计规范“导出”。

卡片

  • 卡片只给并列且可独立阅读的条目使用；不套卡片、不每段一张卡；卡片的外观见视觉设计规范“界面组件的外观”中的“卡片”。
  • 一张卡片一个主题、最多一个主按钮；整张卡片可点击时卡内不再放同目的地按钮。

  • 每个异步操作有四种结果：进行中、成功、失败（原因与重试）、空；每个按钮有可用、禁用（写明原因）、加载中三种状态，加载中不能再次点击。

  • 耗时超过 10 秒的任务（导出、生成、批量处理、智能体运行）显示已用时：每秒更新、结束后定格；智能体按智能体设计规范“耗时与进度”分步、分阶段计时，排队与等待审批单独计时。

标签与状态

  • 同一状态在全系统同名同外观；状态同时用文字表达，不只靠颜色。
  • 标签的尺寸、圆角、字号与放不下时的处理（含商品卡的促销标签）见视觉设计规范“界面组件的外观”中的“标签与状态”。
  • 标签只承载状态与属性，不放营销口号与装饰性的“新”“热”。

头像

  • 用户上传了照片就显示照片；没有照片时显示默认头像，由用户标识固定选取，同一个人在所有页面（含小程序与后台）始终是同一个头像。
  • 未登录、系统账号或无法识别的用户显示通用默认头像。
  • 严禁用文字代替头像：姓名首字、姓氏、拼音首字母、昵称截取、编号或任何其他文字都不行；也不用表情符号字符（不同手机渲染不一致）。
  • 默认头像的画法、头像的形状与各处的尺寸见视觉设计规范“界面组件的外观”中的“头像”。

图表

  • 一张图只回答一个问题；图的标题写结论，不写“某某统计图”。
  • 按数据关系选图：趋势用折线或面积，比较用柱状，占比用环图（5 类以内，超出的小类合并为“其他”），时段与星期两个维度的分布用热力格，排名用横向条形排行。
  • 每张可交互图表都有悬浮提示，显示类别、数值和单位。
  • 图表的配色、线型、数据点、网格、图例、直接标注、提示框的样子和窄屏上的重新布局见视觉设计规范“界面组件的外观”中的“图表”。
  • 数据不够不画图：时间序列少于 3 个时间点改为数字加变化；分类只有 1 类不用环形图，改为一句文字或进度条；不用仪表盘指针图（占空间且难读）。

常用控件做法

以下取主流组件库、平台设计规范与可用性研究的共同做法；新项目先用浏览器调研同类产品核对，再沿用。

控件做法禁止
登录页登录失败统一提示“账号或密码错误”；提交后按钮显示加载并忽略重复点击提示具体是账号错还是密码错
密码框输入框内右侧放眼睛按钮，切换显示与隐藏，按钮有无障碍名称把切换做成框外的勾选项
输入框标签常显；占位文字只放示例；必填用星号标记；有内容才出现清除按钮；限长字段显示字数；失焦时校验，出错后每次输入都重新校验用占位文字代替标签；输入时提前报错
选择器选项多于 10 个时带搜索；选项少于 5 个改用单选或分段长列表无搜索
日期格式 YYYY-MM-DD，时间 HH:mm；范围选择是一个控件：快捷项今日、近 7 天、近 30 天、全部，与自定义起止日期放在同一个弹层里同一系统混用多种日期格式；快捷按钮组与日期选择器并排摆两套
金额输入前缀 ¥，两位小数，手动调整金额用自由输入未经要求给出预设档位代替输入
搜索框左侧放大镜图标，输入即筛选，有内容时出现清除按钮必须再点“搜索”才出结果
后台列表工具栏（左侧搜索与 2–3 个常用筛选，右侧主按钮）→ 状态标签带数量，或可点击的统计卡充当筛选（二选一）→ 表格 → 分页；侧栏已高亮本页时不再放同名标题；打开即是默认视图（见第三层“列表的默认视图”）；带时间字段的列表都有日期范围筛选，数量汇总整个筛选结果；行操作放最后一列，两个文字操作，其余收进“更多”；勾选后出现“已选 N 项”批量栏；首次加载用骨架行；表头吸顶；被截断的单元格悬停显示全文行操作超过三个平铺；统计只算当前页；默认显示“全部”；状态标签与统计卡同时出现
开关只用于立即生效的设置；切换时显示加载，失败自动回滚并提示开关后还要再点保存
对话框居中、带遮罩；右上角关闭按钮与 Esc 都能关闭；表单对话框点遮罩不关闭；焦点锁在框内，关闭后回到触发它的元素；标题与底部按钮固定，内容区滚动贴右侧的抽屉；点遮罩丢失已填内容

案例样本

订餐界面结构

底部导航

只承载一级入口；当前项有明确标识（见视觉设计规范“图标设计方案”），并避让系统安全区。页面栈、返回与重新进入后的位置必须一致。

菜品卡

按图片、名称、规格、价格、可售状态和主行动建立层级；缺货、售罄和不可配送必须有文字状态，不能只用颜色。

套餐选择

弹层先呈现当前选择，再呈现规格、可替换项、加价与数量；关闭、确认和失败恢复保持原选择。

购物车与结算

逐项数量、优惠前后金额、门店、取餐方式、预约时间和支付入口按决策顺序排列；修改数量立即反馈。

优惠券与支付

优惠券选择显示适用范围、门槛和失效原因；支付按钮表达唯一主行动，支付结果与失败重试不和优惠选择混淆。

取餐码

取餐码是履约结果的主信息，同时呈现订单状态、门店、时间与订单查看入口；放大、刷新和过期状态清楚。

端到端网页验收

  • 页面顶部以唯一主标题开始，随后直接进入内容；不得先放页眉、侧栏、品牌块、状态、时间或摘要。原型的品牌标识放在主标题里（图标加系统名），或放在主标题之后的原型框架顶栏里。
  • 检查窄屏、桌面、键盘焦点、长文本、图片缺失、加载、空、错误、成功与禁用状态。
  • 逐个操作走一遍“触发 → 反馈 → 结果 → 返回”：每个按钮按下有反馈、有结果、能回到来源；任何一步断开即不通过。
  • 用浏览器点击导航、弹层、购物车、优惠券、支付、取餐码和后台异常恢复，截图并记录哈希后提交原型批准。

质量门禁

  • 页面没有明确的端与主任务、一个页面承载两种主任务：退回设计。
  • 功能没有分类就决定位置、核心功能可被隐藏或排在营销之后、同一目的地两个入口、同一信息重复：退回设计。
  • 运营内容写死在前台、后台缺少维护动作：退回设计。
  • 导航超过 3 级、当前位置不可见、返回没有回到来源：退回设计。
  • 同一对象的状态切换使用两个并排的控件、切换时位置或尺寸改变、开关的标签随状态改名、禁用没有原因、失败不回滚：退回设计。
  • 新增、删除、加载更多或实时更新让周围内容跳动、把用户的滚动位置拉走，或动画没有减少动态效果的分支：退回修改。
  • 操作列被挤出视口、导航出现第 4 级或祖先不高亮：退回修改。
  • 页面缺少进入方式、目标、主操作、离开方式或五类状态中的任一项，出现孤岛页或死角页：退回设计（检查脚本报错）。
  • 同一页面同一动作两个可见入口、两个按钮做同一件事、文字相同但动作不同、同一目的地两个入口：退回设计（检查脚本报错或警告）。
  • 对象缺少查看、编辑、删除或状态变更且没写理由，状态没有离开事件，流程没有成功终点或失败恢复，异步操作缺少进行中、成功、失败、空中的任一种呈现，按钮缺少禁用原因或加载状态，破坏性操作没有确认：退回设计。
  • 列表没有写明默认视图或默认显示“全部”、终态标签排在待处理前面、状态标签与统计卡重复表达同一组数字：退回设计。
  • 页面标题与导航高亮项同名、导航分组与唯一子项同名、整列为空的列仍然显示：退回修改（原型检查脚本报错）。
  • 驾驶舱只有原始累计数、长期为 0 的指标占主位、卡片时间范围与页面不一致；导出带英文字段名或内部编码：退回修改。
  • 产品界面设计说明没有写参考了哪家组件库的哪个组件：退回设计。
  • 任何宽度下内容被遮挡、手机上不能完整操作：退回修改。
  • 一屏多个主按钮、功能按钮缺少图标、危险操作没有确认、详情与编辑浮层贴右侧滑入：退回修改。
  • 同一个图标代表两个不同对象：退回修改。
  • 颜色、字号、字体、图标图形、层级与阴影、间距与栅格、同类元素外观、表格对齐与内边距、卡片内容越界、文本框聚焦蓝框、横向页面滚动等视觉问题的门禁见视觉设计规范“质量门禁”。
  • 产品前端没有提供外观设置，或违反分端规范中的任一质量门禁：按对应规范处理。
  • 检查脚本只能发现常见写法；脚本通过不等于合规，人工逐类自检不可省略。
